# PI-IOS 新版 pi-host 需求规格

- 状态：REVIEWED（2026-10-30；用户逐项确认 `docs/qa/pi-adaptor-baseline.md` §2 的建议方案）。接口契约仍须另行评审并冻结。
- 范围：PI-IOS 项目内的 iOS 客户端及新版服务端 Host；目标服务器为 `203.0.113.10`，Ubuntu aarch64。
- 依据：本次用户确认的要求；[原 iOS 规格](ios-client.md)、[旧 Host 基础契约](../api/ios-client.md)、[模型服务删除契约](../api/ios-client-provider-remove-draft.md)、[多设备接入草案](../api/ios-existing-host-multidevice-draft.md)、[实现状态](../qa/implementation-status.md)。
- 验证方式：A = 自动化测试，M = 手动检查，A+M = 两者；实际端到端测试应使用隔离数据，不能以本文档或旧版测试记录代替新版证据。

## 已确认决策（原开放问题）

以下内容由用户在 2026-10-30 确认，已从开放问题转为验收依据。实现不得以“旧版如此”为由偏离；若确实需要偏离，必须回到本规格变更并重新验收。

1. **原版 pi 基线与部署**：首版基线固定为 `@earendil-works/pi-coding-agent@1.3.0`，读写现有 `~/.pi` 下的 v3 JSONL 会话；不得静默迁移或重写源文件。Host 安装到独立用户目录，由 systemd user unit 启停，升级采用新版本目录 + 原子切换，保留上一版本用于回滚。已有 pi、会话和项目目录原地保留。iOS 继续负责发起安装和配对。首版只要求 Ubuntu aarch64，不承诺其他系统或架构。
2. **连接与身份**：沿用 SSH 隧道、TOFU 主机指纹确认、一次性配对令牌和每设备令牌。单用户可管理多 Host；多个设备可并发连接；设备可逐台撤销。不兼容旧 Host 协议，也不要求旧 iOS 客户端兼容；旧客户端本地数据不自动迁移到新版接口。
3. **权限模式**：保留 `ask`、`auto`，以及工具权限的 allow-once、allow-session、deny。保留 Plan/Goal 审批和 AskTool。默认 `ask`；权限模式按会话保存，新建会话继承用户当前默认值，修改只影响之后的工具调用，不追溯改写已执行操作。
4. **会话扫描与并发**：扫描当前服务器用户的默认 `~/.pi/agent/sessions` 和已配置 `sessionDir`；首次连接、手动刷新和文件变更时刷新。损坏、不可读或版本不支持的会话可列出但只读，并说明原因。每个会话在 Host 内只有一个写者 actor；写入使用协作 lease，并在追加前后校验文件身份、大小、前缀哈希和追加链。检测到外部写入或无法证明追加成功时立即转为“写入冲突/结果不确定”只读态，不覆盖原文件。Host 不宣称与原版 pi 形成严格互斥；保留全部历史分支、compaction 和未知元数据。
5. **项目与会话操作**：项目对应会话 header 中的工作目录。项目支持选择、注册、改名、归档和本机删除；删除只移除 Host 元数据并写入 project tombstone，重扫不得复活；不改动服务器目录、文件或历史。会话支持新建、续接、改名、归档、搜索、分支和删除；归档与删除状态由 Host tombstone 保存，外部重扫不得意外反转。删除仅在非运行态执行，删除原版 pi 会话文件及该会话拥有的图片。项目删除和会话删除都必须二次确认。保留离线缓存、队列和多 Host 体验；多选批量归档不在首版范围。
6. **Skill 管理**：支持公开 Git 来源与服务器上可访问的本地目录。Git 来源可指定仓库、子目录、branch、tag 或 commit；本地目录可直接选择。安装采用复制到 Host 全局 skills 目录，不直接引用来源目录。每次安装/更新写入不可变版本目录，再以原子指针切换到新版本。运行中的 turn 固定使用启动时解析的版本；每个新 turn 开始前调用 Pi `resourceLoader.reload()`，reload 失败则该 turn 失败且不得回退到未确认的 Skill。删除只删安装副本；同名安装必须显式替换；来源失效需显示失败或结果不确定。iOS 提供列表、详情、安装、更新和删除。
7. **provider 与模型**：沿用 PI-Desktop 的 provider 字段、认证方式和模型/思考档位语义。Host 持久化配置和密钥；查询只返回掩码和是否存在密钥，不返回明文。配置变更只影响之后解析的 turn；每个 turn 开始时固定 provider/model/secret 解析结果，运行中不静默换绑。删除当前绑定或默认 provider 时，清空默认项且后续 turn 必须失败并提示重配；不自动切换到其他 provider。模型发现和验证作为安装/编辑时的可选步骤，但 Host 必须允许手工模型定义。旧 `~/.pi-desktop` provider 不自动迁移；用户需在 v2 Host 重新导入或录入。
8. **图片边界**：20 MB 按原始文件字节计为 20 MiB，允许恰好 20 MiB；每条消息最多 10 张。接受 JPEG、PNG、WebP；动图 WebP 只取首帧，透明通道和元数据不改变限额。允许纯图片消息。不支持视觉的模型必须拒绝图片输入并说明原因。输出保留原格式，保存到会话拥有的受控媒体目录，通过资源句柄读取，不以 base64 持久化。
9. **图片生命周期**：输入和输出图片都随会话保留。媒体使用内容寻址 blob；已提交会话/消息中的不可变引用是权威来源，引用计数只是可重建缓存。会话删除时立即重新扫描引用并删除无其他引用的 blob，失败必须可见且可重试。分支复用 blob 时不复制文件；未被引用的临时上传和孤儿 blob 在 24 小时内清理。未完成上传不得被任何消息引用；消息提交成功前不得把 blob 对外标记为已完成。
10. **流式、中断与恢复**：快照包含已提交文本、工具进度、部分输出、待审批/待输入和当前 turn 状态。断线后续传 cursor；事件缺口回退完整快照。中断请求幂等，未确认时不得显示已中断。审批在 turn 存活期间保持有效；断线时等待，重连后恢复，失效审批不可再提交。Host 持久化 turn attempt 与执行进程组标识；服务进程或服务器重启后，先确认旧进程组已退出或将其终止，再把未完成 turn 标记为中断/结果不确定，不自动续跑。重启产生新事件 epoch，旧 cursor 必须回退快照。不实现 steer；保留排队，新增会话历史与目录搜索。
11. **安全与交付**：首版凭证使用服务用户私有目录中的 0600 原子文件，不依赖额外主密钥。Host 设备记录保存令牌 SHA-256、角色、创建/最近使用/撤销时间；配对令牌一次性且 10 分钟过期；设备令牌可轮换和撤销，撤销后立即关闭该设备的活跃 WebSocket。日志、回执和错误体不得包含明文密钥。WebSocket 只监听 loopback，只通过 SSH 隧道访问。继续交付未签名 IPA、无 APNs、无本地模型、保留离线历史。“不做 GUI”仅排除服务端 GUI；现有 iOS 原生界面继续作为遥控界面。

## 1. 定位、范围与现状

新版 Host 基于原版 pi，为 PI-IOS 提供服务端能力；它与旧 Host 不兼容，不要求实现旧 Host 协议或数据格式兼容。PI-Desktop 仅为历史参考；本任务不修改该项目。新版 Host 的实现代码须位于本项目 `apps/` 下，具体子目录由后续设计决定；需求与契约文档按工作流放在 `docs/` 下。

旧基础契约标记 FROZEN，模型服务删除契约文件头标记 FROZEN，多设备契约为 DRAFT；它们约束的是旧 Host，不能自动作为新版接口契约。旧规格以客户端本地模型清单为准、把图片作为后续能力，且会话删除不包括服务器删除；本需求分别改为 Host 保存配置、支持图片、删除会话时清理服务端图片。旧实现状态矩阵报告了旧 Host 的多项实现与测试，亦记录旧 Host 附件不可用；这些均不是新版已实现或已通过的证据。

用户确认的「现有权限模式」保留原有产品语义；完整规则见上方决策 3。下列验收不定义传输协议、接口字段或内部结构。

## 2. 用户故事

- **US-1** 作为用户，我希望在目标 Ubuntu aarch64 服务器运行基于原版 pi 的新版 Host，通过 iOS 使用它，以便远程工作。
- **US-2** 作为用户，我希望管理服务端全局 Skill，以便所有适用会话能使用经安装或更新的技能。
- **US-3** 作为用户，我希望发现并原地续接原版 pi 会话，以便保留既有上下文和后续历史。
- **US-4** 作为用户，我希望在 Host 管理 provider、API Key 和模型配置，以便更换 iOS 设备后仍能使用服务器配置。
- **US-5** 作为用户，我希望操作项目和会话、查看流式进度并中断任务，以便在手机上控制工作。
- **US-6** 作为用户，我希望使用现有权限模式并处理审批，以便按已选模式控制操作。
- **US-7** 作为用户，我希望发送图片并查看、保存输出图片，以便用图片交流并保留结果。
- **US-8** 作为用户，我希望断线时任务继续，重连后看到最新进度，以便连接中断不会丢失工作进展。

## 3. 验收标准

### 范围与运行环境

- **AC-01（A+M）** Given 目标服务器运行 Ubuntu aarch64，When 部署并启动新版 Host，Then 能由 PI-IOS 连接并完成创建会话、发消息和接收结果的闭环；记录目标机系统与架构、Host 版本及测试证据。
- **AC-02（M）** Given 新版 Host 交付源码，When 检查 PI-IOS 项目目录，Then Host 实现代码位于 `apps/` 下，需求与契约文档位于 `docs/` 下；不要求固定 `apps/` 子目录名。
- **AC-03（M）** Given 新版交付物，When 检查功能与接口文档，Then 基线明确为原版 pi，未声明与旧 Host 兼容；旧契约未被标为新版已冻结契约。

### 全局 Skill

- **AC-04（A+M）** Given 可访问的公开 Git Skill 来源，When 用户安装该 Skill，Then Host 保存安装结果，后续适用的 pi 会话可发现并使用该 Skill；测试检查来源、安装结果和实际可用性。
- **AC-05（A+M）** Given 服务器上可访问的 Skill 目录，When 用户从该目录安装，Then Host 保存安装结果，后续适用的 pi 会话可发现并使用该 Skill。
- **AC-06（A+M）** Given 已安装全局 Skill 且来源有可识别的新内容，When 用户更新，Then 后续适用会话使用更新后的内容；When 用户删除，Then 后续适用会话不再发现该安装项。更新与删除只影响 Host 的安装副本，不修改来源目录或来源仓库。
- **AC-07（A）** Given Skill 来源不可访问或安装、更新、删除失败，When 操作结束，Then 用户可见失败或结果不确定状态，不能显示未经确认的成功。

### 原版 pi 会话、项目与执行

- **AC-08（A+M）** Given 当前服务器用户的默认 `~/.pi/agent/sessions` 或已配置 `sessionDir` 中存在原版 pi 会话，When Host 完成扫描，Then iOS 能看到该会话及已有历史，并能从会话 header 识别其所属项目。
- **AC-09（A+M）** Given 已扫描到的原版 pi 会话，When 用户在 iOS 续接并完成一轮，Then 新消息和结果写回同一原版会话，原有历史可读；随后用原版 pi 打开该会话可看到续接结果，不能仅写入独立副本。
- **AC-10（A+M）** Given 可用项目，When 用户在 iOS 选择项目、新建会话并发送消息，Then 会话在该项目上下文中执行，iOS 可查看发送内容及结果。
- **AC-11（A+M）** Given 会话正在生成输出或执行工具，When 进度产生，Then iOS 在任务完成前逐步显示已收到的文本及工具进度；结束后显示最终状态。
- **AC-12（A+M）** Given 任务正在运行，When 用户请求中断且 Host 确认中断，Then 会话显示中断结果，任务不再继续生成后续输出；失败或结果不确定时不得显示已中断。

### provider 与密钥

- **AC-13（A+M）** Given Host 可用，When 用户新增 provider 及 API Key，Then Host 保存配置与密钥，重新连接或更换 iOS 客户端后可从 Host 查询该 provider 并选择其模型。
- **AC-14（A+M）** Given Host 已保存 provider，When 用户查询并修改配置或替换 API Key，Then 查询反映 Host 保存的配置，成功修改后再次查询能看到更新；用新配置发起的会话实际使用更新后的配置。
- **AC-15（A+M）** Given Host 已保存目标 provider，When 用户删除且 Host 确认成功，Then 目标不再出现在 Host 查询结果中，其 API Key 从 Host 保存的配置中清除，其他 provider 不受影响。
- **AC-16（A+M）** Given 用户在 iOS 输入或查看 provider 配置，When 检查应用持久化数据和日志，Then iOS 不持久保存本地模型配置或 API Key，日志不包含 API Key 明文；输入和传输所需的临时处理不构成本地配置存储。
- **AC-17（A）** Given provider 写操作失败或结果不确定，When iOS 展示结果，Then 不将未确认的写入或删除报告为成功。

### 权限与审批

- **AC-18（A+M）** Given 会话已选择 `ask` 或 `auto`，When 用户应用并执行工具，Then Host 按该模式判定权限，iOS 显示实际生效模式；默认 `ask`，修改只影响之后的工具调用。
- **AC-19（A+M）** Given 某操作按生效权限模式需要审批，When Host 发起审批，Then iOS 展示待审批操作，用户可允许一次、本会话允许或拒绝；Host 按对应选择处理且同一请求不能重复生效。

### 图片输入、输出与清理

- **AC-20（A+M）** Given 会话使用可处理图片的模型，When 用户随一条消息提交 JPEG、PNG 或 WebP 图片，每张不超过 20 MiB 且总数不超过 10 张，Then 图片随消息送达服务端并参与该会话的模型输入。
- **AC-21（A+M）** Given 单张图片超过 20 MiB、单条消息超过 10 张或格式不属于 JPEG/PNG/WebP，When 用户尝试提交，Then 请求被拒绝并说明原因，不把该消息显示为发送成功；恰好 20 MiB 允许提交。
- **AC-22（A+M）** Given 会话中有输出图片，When 用户打开图片，Then iOS 能查看该图片并提供保存操作；保存成功后用户可在保存位置打开图片，失败时显示失败。
- **AC-23（A+M）** Given 会话中已有服务端保存的图片，When 客户端断线后重新连接并打开该会话，Then 图片仍可查看；When 用户删除该会话且 Host 确认删除成功，Then 无其他引用的会话图片立即被清理，仍有引用的图片保留，孤儿临时 blob 在 24 小时内清理。

### 断线与恢复

- **AC-24（A+M）** Given Host 正在运行不需用户响应的任务，When iOS 网络断开而 Host 与执行环境仍正常运行，Then 任务继续运行并可在服务器侧观察到后续进度或完成结果。
- **AC-25（A+M）** Given 客户端断线期间任务产生新进度，When iOS 重连并打开该会话，Then 显示服务端最新进度和当前状态；已完成的任务显示最终结果，仍运行的任务继续显示后续进度。
- **AC-26（A+M）** Given 断线期间任务出现待审批请求，When iOS 重连并恢复会话状态，Then 显示当前仍有效的待审批请求及状态，不把已失效请求显示为可审批；审批在 turn 存活期间保持有效。

### 互操作、事务与协议代际

- **AC-27（A）** Given 固定 `@earendil-works/pi-coding-agent@1.3.0` 和真实临时 `~/.pi`，When 测试扫描、原版 pi 追加、Host 续写、原版 pi 重新打开、分支、compaction、未知记录、损坏尾行与不可读文件，Then 所有受支持场景通过且损坏/冲突场景不覆盖原文件；证据必须来自真实 Pi 进程或 SDK，不可只用 mock。
- **AC-28（A）** Given 在 lease 获取前后、前缀校验后、追加中、fsync 后注入外部写入或 SIGKILL，When Host 恢复或重新扫描，Then 原文件不被覆盖，会话进入只读冲突或结果不确定状态，重启后未完成 turn 不被继续执行。
- **AC-29（A）** Given 上传中断、重复分片、哈希不符、blob 已写但消息未提交、删除时仍被分支引用，When 状态机处理这些事件，Then 未完成上传不可被消息引用，无引用 blob 最终被清理，有引用 blob 保留，客户端只能看到明确成功或失败结果。
- **AC-30（A）** Given 一个 turn 正在使用已安装 Skill，When 同一 Skill 被原子更新，Then 运行中 turn 继续使用原版本，新 turn 在 reload 成功后使用新版本；reload 失败时新 turn 失败且不静默使用旧版本。
- **AC-31（A）** Given 设备 A 与设备 B 已配对，When A 撤销 B 的令牌，Then B 的现有 WebSocket 被关闭且后续请求返回 `UNAUTHORIZED`；服务端不保存令牌明文，日志和响应中无密钥。

## 4. 非目标

- 对旧 Host 提供协议、实现或数据兼容；旧版接口不自动成为新版要求。
- 修改或交付 PI-Desktop 或其他项目；服务端 Host 代码在本项目 `apps/` 下。
- 制作服务端 GUI 或桌面 GUI；现有 iOS 原生界面继续作为遥控界面，不属于本非目标。
- 首版支持 Ubuntu aarch64 之外的系统或架构、私有 Git 来源、插件市场、远程推送或其他未列功能。
